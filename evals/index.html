How I test the assistant

Anyone can build a chatbot that sounds right. I test mine against the ways it can go wrong, and I publish the results.

The first full test run has not happened yet. Results appear here after it does.

How it works

  1. Start from the ways it can fail. Before any score, I wrote down ten separate failure modes: making things up about me, guessing instead of admitting it doesn't know, promising things for me, drifting off topic, obeying instructions hidden in a message, claiming to be human, and a few more.
  2. Test each one on purpose. There are 50 test conversations, including tricks people would actually try, like "ignore your instructions" or pasted text with a hidden command.
  3. Use rules where a rule can decide, and an AI judge only where it can't. Every check is a plain pass or fail, never a 1-to-5 score. Rules check things like formatting, length, leaked instructions and private data. An AI judge, given one narrow question at a time, handles the subjective ones.
  4. Check the judges before trusting them. I labeled 80 answers by hand. Each judge is tested against my labels, and its score only counts if it agrees with me at least 80% of the time on both good and bad answers. Where it doesn't, the page says the score is unverified.

This follows the error-analysis approach taught by Hamel Husain and Shreya Shankar (their episode on Lenny's Podcast) and the judge-validation practice in Arize's documentation. It is my reading of those ideas, not an official implementation.

What these tests can't tell you

  • The labels that grade the judges are mine. They are a first draft until someone else audits them.
  • Twelve test answers per judge is a small sample, so the agreement numbers move around. The ranges shown account for that.
  • The list of failure modes came from how the assistant is meant to behave. Real conversations will find ones I haven't thought of, and I will add them.
